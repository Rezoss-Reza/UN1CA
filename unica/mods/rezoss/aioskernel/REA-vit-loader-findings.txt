VIT model loading / QNN error 30010 -- 2026-10-14

Outcome
  The previous 30010 result was caused by the standalone probe passing Samsung's
  appended metadata to QNN as part of the serialized context. The corrected
  length parses successfully with both the original QNN System API 1.5 library
  and QAIRT 2.44 System API 1.8. The next load stage rejects architecture 81 on
  the tested V73 backend (error 5005). Thus the supplied compiled VIT context
  cannot be retained unchanged for this V73 port.

  This corrects the earlier uncertainty in REA-v73-findings.txt. It is not a
  production APK repair: Samsung's app already removes the trailer correctly.
  No APK/system/vendor changes were made in this investigation.

Trailer format, established in REA and confirmed in the asset
  [base64 JSON of length N][uint32 little-endian N][ASCII SSMT]
  Here N=64. JSON: {"aiosversion": "1.4.00", "fmversion": "3.8.0"}
  The QNN payload ends before the base64 JSON. No model/header bytes are changed;
  the reader passes the adjusted length to QNN.

Samsung Java/provider path (original AIOSKernelService 1.4.28 APK)
  ConstructAdapter.createAdapterConfigVIT:
    reads executor_config.json/vit_model_file_path through the model provider;
    resolves the asset with ModelFileDescriptorCache.getPath.
  ModelFileDescriptorCache.getPath:
    calls FileUtil.getPath$default with default adjust flag enabled.
  FileUtil.getPath$default:
    sets adjust flag true when the default-argument mask contains bit 16.
  FileUtil.getPath / getPathFromCursor$AIOSKernelService_qc_sm8850Release:
    obtains file/container name, asset name, offset and size from provider;
    calls adjustSizeIfNeeded and returns container!asset#offset#adjustedSize.
  FileUtil.adjustSizeIfNeeded:
    reads the last eight bytes at offset + size - 8;
    if SSMT matches, returns size - littleEndianLength - 8.
  D.f(String,long,long), displayed as TailedModelFile in logs:
    separately decodes the trailer's base64 JSON for model verification.
