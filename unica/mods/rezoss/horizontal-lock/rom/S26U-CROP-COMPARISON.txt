Confirmed donor path
--------------------
1. Mode 2 enables horizon leveling in GetHorizonLevelingOverride at
   node 0x7a38c..0x7a3a8. EISOEMConfig supplies the default maximum roll of
   180 degrees at 0x7dcf8..0x7dd1c. This is an angle limit, not a zoom value.
2. GetChromatixTuningHandle chooses mode-specific tuning selectors:
   type 5 value 29 and mode-2 type 6 value 71 at 0x55da4..0x55dec.
3. GetRequestedMarginsAndFrameDelay (node 0x6b520) is called during
   EISV3NodeCreate at 0x31c70 and SetBufferInfo at 0x3dea0. These callers
   establish setup-time margin selection; they are not the frame processor.
4. Initialize resolves eis_get_requested_margins_and_frame_delay into
   node+0x98 at 0x32cf0..0x32d0c. The margin function invokes it at 0x6ba64
   with converted tuning, a dimension, frame rate, batch size and outputs.
5. The algorithm export at 0x59768 goes through its CFI jump table at
   0x161960, then 0x59760, to implementation 0xc0600. It calls 0x9c5b0.
   That helper selects two float margins and an integer frame delay:
   dimension <=1080, <=2160, or above; FPS <=30, <=60, or above.
   For the first bucket, tuning offsets 0/4 hold the margins and 0x50
   holds frame delay. Other buckets select different table entries.
   The helper has no frame ID, current roll or current orientation input.
   These requested margins therefore do not vary with instantaneous tilt.
6. eis_get_stabilization_crop_ratio_ex resolves to algorithm 0x9d260.
   Its success path at 0x9d4a0..0x9d4d0 returns retained fractions:
   (input dimension - total stabilization margin) / input dimension.
   This is a crop ratio, not a hardcoded universal magnification.
7. Init validation at algorithm 0xd0ad4..0xd0b58 checks
   top.eisv3_margins_usage_enhancement and emits an explicit diagnostic
   requesting its override to true when horizon leveling is enabled.
   The diagnostic alone does not prove every downstream override store.
8. Horizon processing is separate: quaternion/reference input reaches
   horizon update at 0xf7bf0. The recording reference is latched at
   0xf7d08..0xf7d1c and changes during recording are warned about/ignored.
   Generic zoom-filter paths also exist in this algorithm. Setup-time
   margins do not prove that every component of final FOV is constant.

Comparison with the S23U experiment
----------------------------------
The earlier default was fixed_crop=0. hl_stream_centered computes the
rotation crop for each matched frame and performs a corner-fit search to fit
the composed perspective matrix into the available domain. Its extra zoom
therefore changes as roll, stock translation and perspective change.
The previous live trace ranged approximately 1.004x..1.400x additional zoom;
this is above the stock camera crop and is not an S26U zoom measurement.
It explains the observed zoom pumping. It does not explain all shaking:
orientation timing, accelerometer filtering and stock-transform composition
remain separate contributors.

The donor reserves a tuning-selected margin budget during setup and performs
orientation correction within its pipeline. That is consistent with an
initial zoom-in and a steady apparent field of view. A fixed extra crop for
the S23U recording is a closer design direction than the adaptive minimum
crop, but it is not proof of an exact S26U implementation.

The new default fixed_crop=1 imposes 2x additional crop. This number is
our experimental budget, not a recovered donor constant. Its saved-video
behavior is unverified. The previous live fixed-crop attempt crashed before
correction writes; synthetic tests do not establish Camera runtime stability.

Cropping provides spare pixels for rotation/translation without exposing
image edges. It does not itself cancel roll; the orientation-derived warp
does that. Center pixels are not intrinsically motionless.

Remaining evidence needed
-------------------------
Resolve the selected donor sensor/mode-2 tuning margins and actual input,
output and pre-crop dimensions; distinguish lens/FOV selection from EIS crop.
An S26U recording trace should compare the configured margins, output_crop_fov,
IPE zoom, and the consumed ICA transforms across tilt. Until that is available,
neither a precise fixed magnification nor perfectly constant final FOV is proven.
The generic 0.2 margin initialization in GetMinTotalMargins must not be quoted
as the resolved mode-2 tuning value.
