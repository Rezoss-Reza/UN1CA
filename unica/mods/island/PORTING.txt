The build now compiles the pinned upstream Java source, not the archived APK.
The unmodified upstream main source/resources are in upstream/source. Native
adapters are under java/dev/android/dynamicisland. prepare-source.py applies
reviewable Java adaptations in /tmp. generate-patches.py emits patch-only smali
integration. Original firmware and out/target smali are never hand-edited.

Menu: UN1CA Settings > UI Settings > Dynamic Island, immediately above live blur.
The entry opens a grouped-card menu with a default-OFF master switch and pages:
- Display: card headers, coloured icons, waveform, haptics and timing.
- Animation: upstream animation choice and preview.
- Position: anchor, offsets, camera-hole placement and pill size with live preview.
- Notifications: heads-up cards, ordinary notifications, progress, verification
  codes and optional auto-copy, plus third-party calling notifications.
- System events: charging, ringer, Bluetooth audio, quick-setting feedback and
  optional privacy/location cards.
- Apps: allow/deny list for ordinary-notification cards.
- Rules: built-in English/Korean dictionaries, custom rules, editors and tests.
- Native diagnostics and upstream version/author/MIT license.

The host Settings package contains the dedicated non-exported SettingsActivity;
there is no separate launcher app, settings provider or root manager. The UI
respects light/dark, theme accent, scalable text and the existing UN1CA wallpaper
transparency preference. English/Korean strings are namespaced to avoid Samsung
resource collisions. Other locales use English fallback.

No LSPosed scope/setup, world-readable preferences, su invocation or root-based
SystemUI restart action is shipped. Root availability does not bypass Android's
app sandbox; the integration uses the permissions already held by the privileged
Settings and SystemUI processes. Changes apply through Settings observers.

Settings.Global.unica_dynamic_island is the saved device-wide master switch.
Settings.Global.unica_dynamic_island_config is the shared JSON configuration.
Configuration reload is event-driven; there is no four-second preference poll.
Typed values and app sets are preserved. Editors merge with the latest saved
configuration. Oversized imports are rejected with a visible message while the
previous saved settings remain intact. Preview broadcasts require
WRITE_SECURE_SETTINGS and authenticated sender identity.

SystemUI integration:
- The existing native lifecycle adapter captures Samsung controllers and forwards
  ongoing activity/call/cast changes, shade fraction, dozing and window state.
- The upstream source handles media, ordinary notifications, rule/progress cards,
  system events, interactions and layout. Dictionaries are embedded in Java so
  DEX-only APK packaging cannot silently omit them.
- Notification-list snapshots run only on the pre-group pass. Native row filtering
  preserves stock filtering when the feature is OFF or not ready.
- The original heads-up decision runs first. Only a stock-approved system pin
  accepted by a ready island is taken over; explicit user pinning remains stock.
- Stock chips are hidden only after a successful window attachment. Failure turns
  the master switch OFF. OFF restores saved stock visibility, launcher targets,
  filtering and heads-up behavior, and releases media callbacks/audio capture.
- Event/output listeners are registered once per SystemUI process and reused;
  OFF gates UI refresh and event presentation. There is no duplicate listener
  registration on OFF -> ON. Main-handler refresh/reveal flags are reset on OFF.
- Stock shade card/media rendering and lockscreen/AOD Now Bar are retained.
  Upstream ShadePerf and external LiveBridge integration are not installed.

The new engine replaces the earlier dev.flexy.dynamicisland renderer. The old
module and Settings XML/patch were backed up before replacement. customize.sh
rejects a decoded SystemUI which already contains the old native port: build from
a clean target rather than layering engines. Do not hand-remove generated smali.

Runtime classes are added to smali_classes6 (stock SDK37 input has five DEX files).
Settings UI/backend classes use its next DEX, smali_classes5, plus the existing
availability controller in smali_classes4. Validation checks contiguous DEX
indexes, unique class definitions and absence of old/Xposed runtime dependencies.

Source/build files:
  build.sh                 Java/D8 compile and patch generation
  prepare-source.py        explicit upstream-to-native Java adaptation
  generate-patches.py      native call/guard/menu patch generation
  patches/0001-*           source-built runtime classes
  patches/0002-*           native SystemUI event/notification integration
  ../settings/.../0007-*   menu classes, availability controller and activity
  ../settings/SecSettings.apk/res/.../unica_island*.xml  menu and strings
The Settings controller remains in the normal Settings patch tree, so the source
XML can resolve it even when the island mod is disabled. Its capability property
hides the entry on unsupported/disabled builds. Supported target: dm3q, SDK37.

Reproduce patches (no full ROM build or deployment):
  source ./buildenv.sh dm3q
  # Decode the exact stock SystemUI input and current Settings to NEW /tmp dirs.
  # Supply a SystemUI decode which has no island integration already applied.
  unica/mods/island/build.sh /tmp/clean-SystemUI /tmp/clean-Settings

Tests:
  python3 unica/mods/island/tests/run.py
  python3 unica/mods/island/tests/run-config.py /path/to/json-20250107.jar
The second command uses org.json:json:20250107 only as a host test dependency
(SHA256 pinned in the test); Android supplies org.json in the ROM.
